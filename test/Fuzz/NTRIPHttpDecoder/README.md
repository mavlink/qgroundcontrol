# NTRIP HTTP decoder fuzzing

This standalone entry point links the production `QGC::GPSNTRIPHttp` target, not a copy of
the decoder. It needs Qt 6.8 or newer **Core and Network only**. Its default build also
compiles the HTTP public-header checks and consumer from `test/GPS/Standalone`.
It does not change the MAVLink ClusterFuzzLite image, dependencies, or fuzzing budget.

## Deterministic smoke test

```bash
cmake -S test/Fuzz/NTRIPHttpDecoder -B build/ntrip-fuzz \
  -DCMAKE_PREFIX_PATH="$QT_ROOT_DIR"
cmake --build build/ntrip-fuzz --parallel 2
ctest --test-dir build/ntrip-fuzz --output-on-failure -L Unit
```

The smoke runner exercises 39 representative HTTP/ICY seeds, truncated prefixes, and
deterministically generated byte streams without a network service or fuzzing runtime.
The seeds cover lengths, chunks/extensions/trailers, informational responses, source tables,
Retry-After dates and integers, error previews, malformed framing, and parser limits.

## Clang libFuzzer with ASan and UBSan

```bash
cmake -S test/Fuzz/NTRIPHttpDecoder -B build/ntrip-fuzz-asan \
  -DCMAKE_PREFIX_PATH="$QT_ROOT_DIR" -DCMAKE_CXX_COMPILER=clang++ \
  -DQGC_NTRIP_LIBFUZZER=ON
cmake --build build/ntrip-fuzz-asan --parallel 2
ctest --test-dir build/ntrip-fuzz-asan --output-on-failure -L Unit
build/ntrip-fuzz-asan/ntrip_http_decoder_smoke --write-corpus build/ntrip-fuzz-corpus
mkdir -p build/ntrip-fuzz-artifacts
build/ntrip-fuzz-asan/ntrip_http_decoder_fuzzer build/ntrip-fuzz-corpus \
  -dict=test/Fuzz/NTRIPHttpDecoder/NTRIPHttpDecoderFuzzer.dict \
  -max_len=65536 -max_total_time=60 -timeout=10 -rss_limit_mb=512 \
  -artifact_prefix=build/ntrip-fuzz-artifacts/
```

The harness bounds input to 64 KiB and uses one-byte, seven-byte, whole-input, and
input-derived fragmentation. It checks bounded output, single connection/failure publication,
bounded retry hints, repeated EOF, and reset recovery both after EOF and mid-response.
It deliberately does not compare diagnostic text across fragmentation: error-body previews
are bounded and best-effort. Qt itself is the installed SDK; the production parser,
configuration, and harness are sanitizer-instrumented.

## Local compatibility checks

To check the advertised minimum, point `QT_ROOT_DIR` at a Qt 6.8.3 SDK and repeat the
smoke commands in a separate build directory. Only the Qt base package is needed.
On Windows, use the MSVC 2022 Qt kit from a Developer PowerShell:

```powershell
cmake -S test/Fuzz/NTRIPHttpDecoder -B build/ntrip-fuzz-qt68 -G Ninja `
  "-DCMAKE_PREFIX_PATH=$env:QT_ROOT_DIR"
cmake --build build/ntrip-fuzz-qt68 --parallel 2
ctest --test-dir build/ntrip-fuzz-qt68 --output-on-failure -L Unit
```

For the full NTRIP suites and public consumers, configure `test/GPS/NTRIP/Standalone`
in another build directory with Qt Positioning installed, then build and run CTest.
Those TLS/reentrancy fixtures use loopback sockets and ephemeral ports, not external
casters.
